# 课程题库题目挂载能力 Issue 说明

## 背景

当前编程题默认只面向首页/全部题目场景，后续需要支持教师在新增、修改、删除题目时，将题目挂载到指定课程下，并控制该题是否同时出现在首页刷题列表。

本次采用的产品语义：

- `is_public` 控制题目是否出现在首页/全部题目。
- `course_ids` 控制题目是否出现在课程题库。
- 不传 `is_public` 时，继续保持旧行为：默认进入首页题库。
- `is_public=false + course_ids=[courseId]` 表示课程私有题，只在该课程下可见。

## 目标

- 新增题目时支持选择挂载到课程。
- 新增题目时支持只进入首页、只进入课程、同时进入首页和课程。
- 更新题目时支持修改或清空课程挂载关系。
- 课程题库列表可以查询课程内题目。
- 首页题目列表仍只展示 `is_public=true` 且已发布的题目，避免课程私有题泄露。
- 课程私有题详情只允许课程成员、题目创建者或管理员访问。

## 数据模型改动

`Problem` 新增字段：

```go
CourseIDs []primitive.ObjectID `bson:"course_ids,omitempty" json:"course_ids,omitempty"`
```

字段含义：

| is_public | course_ids | 可见范围 |
| --- | --- | --- |
| `true` | `[]` | 首页/全部题目 |
| `false` | `[courseId]` | 指定课程题库 |
| `true` | `[courseId]` | 首页和指定课程题库 |

## 请求参数改动

### 创建题目

`CreateProblemRequest` 新增：

```go
CourseIDs []string `json:"course_ids"`
```

同时新增 `EffectiveIsPublic()`，用于兼容旧客户端：

- 未传 `is_public`：默认 `true`
- 显式传 `false`：按课程私有题处理

示例：

```json
{
  "title": "数组求和",
  "description": "给定一个数组，计算所有元素之和并输出结果。",
  "difficulty": "easy",
  "is_public": false,
  "course_ids": ["507f1f77bcf86cd799439011"]
}
```

### 更新题目

`UpdateProblemRequest` 新增：

```go
CourseIDs *[]string `json:"course_ids"`
```

这里使用指针是为了区分：

- 不传 `course_ids`：不修改课程挂载关系
- 传 `course_ids: []`：显式清空课程挂载关系

## 接口改动

### 新增课程题库列表接口

```http
GET /api/v1/courses/:courseId/problems
```

查询规则：

- 只查询 `course_ids` 包含当前课程 ID 的题目。
- 只返回 `status=published` 的题目。
- 不要求 `is_public=true`，因此课程私有题可以在课程下显示。

权限规则：

- 管理员可查看。
- 课程创建者、任课教师可查看。
- 已加入课程班级的学生可查看。

## 权限边界

### 创建/更新题目挂载课程

教师将题目挂载到课程时，需要拥有课程管理权限：

- 课程创建者
- 课程任课教师
- 管理员

这样可以避免教师把题目挂到自己无权管理的课程。

### 查看题目详情

如果题目是公开题：

- 所有人可查看。

如果题目是课程私有题：

- 管理员可查看。
- 题目创建者可查看。
- 对应课程成员可查看。
- 未登录用户或非课程成员不可查看。

### 删除题目

本次调整后：

- 管理员可以删除全部题目。
- 教师可以删除自己创建的题目。

后续如果题目被多个课程复用，建议再扩展“从课程移除”和“软删除”，避免直接删除影响其他课程。

## 后续建议

### Mongo 索引

建议上线前增加索引：

```js
db.problems.createIndex({ is_public: 1, status: 1, unique_id: 1 })
db.problems.createIndex({ course_ids: 1, status: 1, created_at: -1 })
db.problems.createIndex({ created_by: 1, status: 1, created_at: -1 })
```

### 数据迁移

现有题目可以补齐 `course_ids`：

```js
db.problems.updateMany(
  { course_ids: { $exists: false } },
  { $set: { course_ids: [] } }
)
```

### 后续扩展

如果后续需要课程内排序、章节归属、课程内题目备注、公共题引用到课程等能力，建议新增关联集合：

```js
course_problems {
  course_id,
  problem_id,
  created_by,
  sort_order,
  chapter_id,
  created_at
}
```

当前阶段先使用 `Problem.course_ids`，改动更小，也更贴近现有 Mongo 模型。
