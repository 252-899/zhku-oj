# AI 生成题目草稿保存 Issue 说明

## 背景

教师使用 AI 生成 OJ 编程题后，不一定会保存全部题目，也可能希望每道题分别配置是否公开到首页题库、是否挂载到某个课程题库。原生成接口只负责流式返回题目内容，缺少后续确认保存流程，前端无法稳定地把“某一道 AI 生成题”映射到正式题库记录。

## 目标

- AI 生成题目完成后，后端先把生成结果保存为 Mongo 草稿。
- SSE 原有 `questions` 响应结构保持兼容，只额外返回 `draft_id` 和 `expires_at`。
- 前端提交保存请求时，可以逐题选择 `is_public` 和 `course_ids`。
- 被选中的题目写入正式 `problems` 和 `test_cases`。
- 未选中的题目在草稿中标记为 `discarded`，后续由过期时间清理。

## 方案

采用“生成结果草稿 + 二次确认保存”方案：

1. `POST /api/v1/ai/oj-question-gen/stream` 继续负责 AI 题目生成。
2. 生成完成并进入 `waiting_confirmation` 事件时，后端创建 `ai_generated_problem_drafts` 草稿。
3. SSE 响应在原 `data.questions` 外补充：

```json
{
  "draft_id": "661f...",
  "expires_at": "2026-04-20T10:00:00Z"
}
```

4. 前端调用 `POST /api/v1/ai/oj-question-gen/save` 保存选中题目：

```json
{
  "draft_id": "661f...",
  "items": [
    {
      "generated_problem_id": "gen_1",
      "is_public": true,
      "course_ids": []
    },
    {
      "generated_problem_id": "gen_2",
      "is_public": false,
      "course_ids": ["661f..."]
    }
  ]
}
```

## 权限边界

- 只有教师和管理员可以保存 AI 生成题目。
- 普通教师只能保存自己生成的草稿。
- 普通教师挂载课程时，必须拥有该课程管理权限。
- 管理员可以保存和挂载任意课程。
- `is_public=false` 时必须至少挂载一个课程，避免题目既不公开也不属于任何课程。

## 数据写入规则

- 保存成功的题目状态为 `published`。
- `is_public=true` 的题目出现在首页/全部题目。
- `course_ids` 控制题目是否出现在课程题库。
- 生成题目的标准代码和标准语言会写入正式 `Problem`，方便后续评测或题解展示扩展。
- 测试用例保存失败时，会尽量回滚已创建的正式题目和测试用例，避免出现半成品题目。
